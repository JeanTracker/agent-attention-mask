## Stop 이후 WAITING 구간은 덮지 않는다 — 규격 고정 (2026-09-09)
- 사용자 지시: "사용자의 프롬프트를 즉시 실행할 수 있는 `Stop`이 온 이후에는 matrix로 가리면 안 됨."
- **현재 구현이 이미 만족한다.** `_should_cover`는 `_busy_since`가 있어야 참이고, WAITING 이벤트는 `_busy_since`를 지운다(`_handle_hooks`). `_tick`도 훅이 WAITING을 말하는 동안 매 사이클 지우고, `_hooks_speaking()`은 WAITING을 만료시키지 않으므로(`HOOK_STALL`은 BUSY만 탄다) 덮기로 돌아갈 경로가 없다. 코드 변경 없음.
- **문장 범위를 좁혀 읽었다**: "`Stop` 이후"는 새 턴이 열리기 전까지의 WAITING 구간이다. 문자 그대로면 첫 `Stop` 이후 영구히 덮지 못한다. 주입된 알림이 연 턴은 뒤에 실제 작업이 따라오므로(D-031) 덮는 쪽이 맞다.
- **기록**: D-035(D-034를 판정에서 요구사항으로 승격). HRQ-005의 2번 항목(백그라운드 중 유휴 재진입 지연)은 이 결정으로 해소 처리하고, D-035를 SC 항목으로 승격할지를 3번으로 추가했다 — SC 수정은 단독 확정 대상이 아니다.
- **검증**: 8개 스위트 **169개 항목 전부 통과** (실패 0, 165 → 169). 신규 4개: `Stop(background_tasks 있음)` 뒤 서브에이전트 이벤트가 계속 오고 11초가 지나도 재진입 없음(`OVERLAY_DELAY` 1.5초로 조여 8회분 여유), 주입 전 유휴 구간 무덮음, 주입된 알림이 연 턴은 덮음, 그리고 전제 확인. **역대조 완료** — `WAITING` + `background_tasks` 비어 있지 않음을 BUSY로 바꾸는 패치(D-034가 기각한 방향)를 임시로 넣으면 신규 2건이 `t=3.02`·`t=2.52`에 실패하고, 되돌리면 통과한다.
- **이 규칙이 덮지 못하는 경로**: 인터럽트에는 아무 훅도 발화하지 않아 WAITING 구간이 시작되지 않는다. `HOOK_STALL` 120초까지 덮인 채로 남는 것은 그대로다(실측 문서의 (b)).

## `q` 억제의 해제 경계를 사용자 제출 프롬프트로 좁혔다 (2026-09-16)
- **사용자 확인 요청**에서 출발했다 — "`q`를 누르면 그 사용자 요청에 대해서는 mask가 더 안 나오는 게 맞나, 그 요청으로 서브에이전트가 도는 경우도 마찬가지여야 한다".
- **서브에이전트는 이미 만족했다.** `_should_cover`가 `_skip_turn`을 첫 줄에서 보고 나가므로 서브에이전트 출력이 `_busy_since`를 세워도 덮이지 않고, 서브에이전트의 BUSY 이벤트는 `agent_id` 규칙(D-033)에 걸러져 해제 분기까지 가지 않는다. 회귀 테스트로 고정했다(수정 전에도 통과).
- **깨지던 경로 하나를 찾아 고쳤다(D-038).** 백그라운드 작업 완료 시 하네스가 주입하는 `<task-notification>` 프롬프트(D-031)의 `UserPromptSubmit`이 `_skip_turn`을 풀어, `q`로 건너뛴 요청이 띄운 서브에이전트가 완료를 보고하면 같은 요청 도중 레인이 다시 덮였다. 실측 재현 `t=7.54`. `_is_injected_prompt` 판정이 해제 분기보다 뒤에 있던 것이 원인이고, 해제를 "주입분이 아닌 `UserPromptSubmit`"으로 한정했다. 상태 판정(주입된 턴도 BUSY)은 건드리지 않았으므로 D-035의 `test_the_injected_notification_turn_still_covers`는 그대로 통과한다.
- **검증**: 8개 스위트, phase9 훅 스위트 전부 통과(신규 2개 포함). `test_phase3_overlay.py`는 전체 실행에서 2회 모두 `busy_then_read.py` 픽스처를 쓰는 feed 테스트 하나가 20초 타임아웃으로 죽었다(1회차 `test_mouse_click_wakes_without_injecting_garbage`, 2회차 `test_wake_key_is_not_forwarded_to_the_agent` — 매번 다른 항목). **단독 실행에서는 16개 전부 통과.** 인과 없음을 **기준선으로 반증했다** — 변경을 stash하고 돌린 전체 실행에서도 `test_wake_key_is_not_forwarded_to_the_agent`가 동일하게 20초 타임아웃으로 죽는다. 이번 변경은 `_handle_hooks` 안쪽만 건드리고 phase3는 훅 이벤트를 하나도 쓰지 않으므로 코드 경로로도 닿지 않는다. 즉 전부터 있던 부하 플레이크이고(2026-09-10 항목과 같은 성질, 방향은 반대 — 그때는 단독 실행에서 1회), 별도 조사 대상으로 남긴다.
- README 「동작」 절의 `q` 문단에 "같은 요청의 서브에이전트·백그라운드 완료 보고도 다시 덮지 않는다, 해제는 사용자가 직접 제출한 다음 프롬프트"를 명시했다. `_seconds(...)` 상수는 변경 없으므로 「타이밍 조정」은 그대로다.

## 기본 설정 파일 + TUI 복수 선택 (2026-09-17)
- 사용자 지시: "기본 설정을 지정하는 기능을 넣어 새 세션부터 적용하게 해주고, tui에서는 세션을 복수 선택하여 기본 설정으로 적용할 수 있게." D-041로 기록했다.
- `amask/config.py` 신설. `~/.amask/config.json`(0600), 세 키만, 원자적 교체. 우선순위는 `코드 기본값 < 파일 < env < 세션 set` — env가 파일보다 위인 이유는 env가 한 번의 실행에 붙는 값이라서다. 이를 구분하려고 코드 기본값을 `SHIPPED_*`로 분리했고, `_seconds(...)` 세 상수는 이름과 역할을 그대로 뒀다(CLAUDE.md가 README 「타이밍」과 대응시키는 그 세 개).
- **러너는 파일을 감시하지 않는다.** 감시하면 "이 값을 이 세션에서 누가 덮어썼는가"를 매 폴링마다 판정해야 하고 그게 화면을 덮을지를 결정한다 — 상태 판정 입력을 하나 늘리는 셈이다. 사용자 요구도 "새 세션부터"였다.
- `amask --config`는 저장값과 **새 세션이 시작할 값**을 함께 보여준다(env가 걸리면 갈라지는 지점). `키=값`으로 지정, `키=`으로 삭제. 검증은 `Settings.update`를 재사용한다.
- TUI: `space` 표시, `a` 전체, `d` 표시한 세션에 기본 설정 적용. 대상 규칙을 "표시가 있으면 표시된 것 전부, 없으면 커서 하나"로 통일해 `s`·`w`·`+/-`도 따른다. 표시는 pid로 들고 사라진 세션은 자동 해제한다.
- 손 검증: `--config overlay_delay=11` 후 새로 띄운 세션이 `get`에서 `overlay_delay: 11.0`으로 응답했다. 표시 2개 + `d`의 프레임도 pty에서 확인했다.
- **픽스처 버그 하나**: `window.instr(y, x, n)`의 `n`이 문자가 아니라 바이트로 세어져 한글 줄이 잘렸다 — 화면은 정상인데 키 안내가 클리핑된 것처럼 보였다. 길이 인자를 없애 해결. 덤으로 도움줄이 105셀이라 96칼럼에서 실제로 잘리는 것이 드러나 95셀로 줄였다.
- **검증**: 제어 채널 스위트 **132개 항목 전부 통과**(93 → 132). 전체 9개 스위트 **315개 항목**, 실패는 phase3의 `test_wake_key_is_not_forwarded_to_the_agent` 1건 — 같은 날 기준선으로 반증한 기존 부하 플레이크와 동일 항목이다(전체 실행 5회 중 4회, 단독 실행은 매번 통과).

## 배포용 설치 가이드 + 심링크 설치 버그 (2026-09-21)
- 사용자 지시: "사람들이 설치할 수 있게 가이드 줘야지? 나만 쓰려고 하는 것은 아니야." 그 앞의 두 질문 — "셸스크립트에 등록되는 건 아니지?", "claude 명령어에 amask claude로 등록해야겠네" — 이 실제 내용이다. D-042로 기록했다.
- **README가 권하던 심링크 설치가 동작하지 않았다.** `bin/amask`가 `os.path.abspath(__file__)`로 저장소 루트를 잡는데 `abspath`는 심링크를 풀지 않는다. 스크래치에 심링크를 걸어 실행해 `ModuleNotFoundError: No module named 'amask'`로 재현했고 `realpath`로 고쳤다. 같은 방식으로 재실행해 `--help`가 뜨는 것을 확인했다. 이 항목은 감수자 지적으로 찾았다 — 문서를 먼저 고쳤으면 남에게 깨진 절차를 넘길 뻔했다.
- **훅 명령 문자열에 따옴표가 없었다**(`hooks.py`). 공백이 든 경로에 클론하면 emitter 경로가 두 인자로 갈라져 훅이 조용히 안 뜬다 — 상태 판정이 D-025의 훅 대신 타이밍 휴리스틱으로 떨어지고, 증상은 "가끔 안 가려진다"라서 원인을 찾기 어렵다. `shlex.quote`를 씌우고 `/tmp/dir with space/...`로 조립 결과를 확인했다.
- README 「Installing and running」을 다시 썼다. 요구사항 → clone → PATH에 있는 디렉터리로 심링크(`~/bin`은 macOS 기본 PATH가 아니다) → `### Wrapping claude by default` → `### The iTerm2 scrollback setting`(기존 문단 그대로) → `### Uninstalling`.
- alias 안내에서 `type claude`를 먼저 시킨다. 구버전 설치는 `~/.claude/local/claude`를 PATH에 올리지 않고 alias로 연결하므로, 거기에 `alias claude='amask claude'`를 덮으면 amask가 ENOENT로 죽는다. 이 저장소가 돌고 있는 기계는 `/Users/.../.local/bin/claude`(native installer)라 이 경우가 아니었고, 그래서 손으로는 재현하지 못했다 — 문서에만 반영했다.
- 재귀 위험은 "PATH 셔임 일반"이 아니라 **"이름으로 `claude`를 다시 부르는 셔임"**이라고 적었다. 절대경로를 exec하는 셔임은 동작한다. 처음에 사용자에게 셔임 전체가 재귀한다고 답했던 것을 문서에서는 정확히 고쳤다.
- **검증 (2026-09-21)**: `python3 tests/run_all.py` 9개 스위트 **322개 항목 전부 통과**, 실패 0, 종료코드 0. 연속 두 번 실행해 둘 다 통과했다 — 앞선 날짜들에서 계속 걸리던 phase3의 `test_wake_key_is_not_forwarded_to_the_agent` 부하 플레이크도 이번 두 번에서는 나오지 않았다(고친 것이 아니라 관측되지 않았을 뿐이다). 별도로 심링크 실행(`--help` 출력)과 공백 경로에서의 훅 명령 조립을 손으로 확인했다.
- **다중 셸 보강 (2026-09-21)**: 사용자 지시 "bash 등 다양한 쉘 지원 필요". bash·zsh·ksh는 alias 한 줄로 묶고 rc 파일만 갈라 적었다(`~/.zshrc`, 리눅스 `~/.bashrc`, macOS 로그인 셸 `~/.bash_profile`). fish는 함수 + `funcsave`로 따로, 제거 절차에도 `~/.config/fish/functions/claude.fish`를 넣었다. 우회 수단 대표를 `\claude`에서 모든 셸에 통하는 `command claude`로 바꿨다.
  - 가짜 `amask`를 PATH에 올려 bash 3.2(`--rcfile`)와 zsh에서 `type claude`·alias 인자 전달·`command` 우회를 실제로 확인했다. bash는 "claude is aliased to", zsh는 "claude is an alias for"로 문구가 달라서 README에서 출력 예시를 그대로 인용하던 문장을 뺐다.
  - **fish는 검증하지 못했다** — 이 기계에 없다. 문서에 그 사실을 적어뒀다(D-042). README 외 변경 없음이라 스위트는 재실행하지 않았다(직전 322개 전부 통과가 마지막 코드 상태 그대로다).
- **fish 제거 (2026-09-21)**: 사용자 지시로 fish 관련 서술(함수 + `funcsave`, 제거 절차의 `claude.fish`, 미검증 단서 문단)을 전부 뺐다. 검증할 수 없는 명령을 설치 가이드에 두지 않는다는 판단이고, 가이드가 다루는 셸은 bash·zsh·ksh다. D-042의 해당 항목도 이 결론으로 다시 적었다.

## `--top` 상세 화면과 스크롤 (2026-09-21)
- 사용자 지시 둘: "amask top tui에 엔터 선택 시 해당 세션의 상태를 더 자세히 보여줄 수 있을까?" → D-043, 뒤이어 "화면 높이가 짧은 경우 짤리고 네비게이션이 안되네" → D-045.

- **목록도 같은 버그였다.** `_draw`가 창 높이에서 그리기를 멈출 뿐이라 세션이 많으면 뒤쪽이 아예 보이지 않았고 커서를 옮겨도 화면이 따라가지 않았다. `visible_span`으로 커서를 가운데 두고 따라가게 하고, 상세는 오프셋을 `_draw_detail`이 깎아서 돌려주도록 했다. 제목 오른쪽에 `↑3 ↓12`로 화면 밖 줄 수를 적는다 — 짧은 창과 짧은 내용을 구분해 주는 것이 이번 신고의 절반이다.
- **작업 환경 특이사항**: 같은 워킹트리에서 다른 Claude 세션이 동시에 `top.py`·README·`DECISIONS.md`를 고치고 있었다(그쪽이 D-044로 목록 열을 재구성). 번호가 겹쳐 이쪽 결정을 D-045로 옮겼고, 그쪽 라벨 변경(`요청`→`프롬프트`)에 맞춰 테스트 단정 하나를 라벨에 의존하지 않게 고쳤다. 전체 스위트를 두 세션이 동시에 돌리면 pty 타이밍을 두고 경합한다.
